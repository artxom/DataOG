# 华为云 GaussDB(DWS) 9.1 / 8.3 SQL 语法与 DDL 规范

> 适用版本：Huawei Cloud GaussDB(DWS) 9.1（兼容 8.3） | 方言标识：`DWS` | 协议通道：PostgreSQL 兼容增强分布式 MPP

## 1. 存储引擎选型（ROW / COLUMN / HSTORE_OPT）

GaussDB(DWS) 支持行存、列存与实时混合存储引擎，建表时通过 `ORIENTATION` 与 `TBLPROPERTIES` / `WITH (...)` 指定：

- **ROW（行存）**：适合高并发点查、单行高频更新、小表维表与事务型写入。
- **COLUMN（列存）**：适合 OLAP 大宽表、聚合分析、高压缩比批量写入（`COMPRESSION = LOW | MIDDLE | HIGH`）。
- **HSTORE / HSTORE_OPT（实时高并发存储）**：适合高频实时 Upsert/Delete 与实时分析混合场景；DWS 9.1 推荐 `HSTORE_OPT`。

```sql
-- 标准列存事实表模板
CREATE TABLE dw.dwd_order_detail (
    order_id      BIGINT NOT NULL,
    cust_id       BIGINT NOT NULL,
    order_date    DATE NOT NULL,
    amount        NUMERIC(18, 2),
    region_code   VARCHAR(16)
)
WITH (
    ORIENTATION = COLUMN,
    COMPRESSION = MIDDLE
)
DISTRIBUTE BY HASH(cust_id);

-- HSTORE_OPT 实时高频更新表
CREATE TABLE ods.rt_account_balance (
    acct_id       BIGINT NOT NULL,
    balance       NUMERIC(18, 2),
    updated_at    TIMESTAMP,
    PRIMARY KEY (acct_id)
)
WITH (
    ORIENTATION = COLUMN,
    ENABLE_HSTORE_OPT = ON
)
DISTRIBUTE BY HASH(acct_id);
```

## 2. HStore Opt 与 Binlog 实时增量捕获（DWS 9.1 / 8.3）

DWS 9.1 / 8.3 在 `HSTORE_OPT` 表上提供 **Binlog** 增量变更流能力，用于实时数仓下游同步与 CDC：

- 开启开关：`ENABLE_BINLOG = ON`（表级属性或集群 GUC 参数）。
- 变更时间戳：`enable_binlog_timestamp = on`，在 Binlog 元信息中保留精准变更时间。
- 后台清理并发：`autovacuum_max_workers_hstore` 控制 HStore 专用 autovacuum worker 数量，缓解高吞吐写入膨胀。
- **关键冲突约束**：`ENABLE_BINLOG = ON` 与列存 Delta 表参数 `ENABLE_DELTA = ON` **互斥**，不可在同张表上同时开启。

```sql
CREATE TABLE ods.rt_user_profile (
    user_id     BIGINT NOT NULL,
    tier        VARCHAR(32),
    updated_ts  TIMESTAMP,
    PRIMARY KEY (user_id)
)
WITH (
    ORIENTATION = COLUMN,
    ENABLE_HSTORE_OPT = ON,
    ENABLE_BINLOG = ON
)
DISTRIBUTE BY HASH(user_id);
```

## 3. 分布方式与主外键/唯一约束铁律

DWS 为 MPP Shared-Nothing 分布式架构，建表必须显式规划 `DISTRIBUTE BY`：

- `DISTRIBUTE BY HASH(col1 [, col2])`：按 Hash 散列到各 DN，适用于中大型事实表/宽表。
- `DISTRIBUTE BY REPLICATION`：全 DN 复制，仅适用于低频更新的小维度表（通常 < 100 万行）。
- **核心约束铁律**：
  1. `PRIMARY KEY` 与 `UNIQUE` 约束 **必须包含所有的分布键列**（若为分区表，通常还需包含分区键列）。
  2. 分布键字段类型禁止为 `TEXT`（大字段）、`FLOAT`/`DOUBLE`（精度漂移风险），推荐 `BIGINT`、`INT`、`DATE`、`VARCHAR(N)`。
  3. 外键约束在分布式大表通常仅作设计文档声明，生产 ETL 常依赖业务校验以减少跨 DN 锁开销。

```sql
-- 正确：复合主键包含分布键 user_id 与分区键 dt
CREATE TABLE dm.user_daily_agg (
    dt        DATE NOT NULL,
    user_id   BIGINT NOT NULL,
    pv        BIGINT,
    PRIMARY KEY (user_id, dt)
)
WITH (ORIENTATION = COLUMN)
DISTRIBUTE BY HASH(user_id)
PARTITION BY RANGE (dt) (
    PARTITION p202601 VALUES LESS THAN ('2026-02-01'),
    PARTITION pmax    VALUES LESS THAN (MAXVALUE)
);
```

## 4. Range/List 分区与自动分区 `time_format`

DWS 支持静态 Range/List 分区与按时间间隔的 **自动分区（Automatic Partitioning）**：

- 当分区键为标准 `DATE` / `TIMESTAMP` 时，可直接配合 `INTERVAL ('1 day')` 或 `INTERVAL ('1 month')` 自动扩展分区。
- **非日期类型时间列自动分区（`time_format`）**：DWS 9.1 / 8.3 支持对 `INT4`、`INT8`、`VARCHAR`、`TEXT` 类型的时间编码列（如 `20260401` 或 `'2026-04-01'`）指定 `time_format` 实现自动分区，无需重构历史表结构。

```sql
-- 对 VARCHAR 类型日期列使用自动分区（语法示意，具体参数随集群版本核验）
CREATE TABLE dwd.fact_txn_str_dt (
    txn_id    BIGINT NOT NULL,
    stat_dt   VARCHAR(8) NOT NULL,
    amt       NUMERIC(18, 2)
)
WITH (ORIENTATION = COLUMN)
DISTRIBUTE BY HASH(txn_id)
PARTITION BY RANGE (stat_dt) INTERVAL ('1 month') (
    PARTITION p_init VALUES LESS THAN ('20260101')
);
```

## 5. 冷热表（OBS 分层）、Disk Cache 与预热（DWS 9.1）

DWS 9.1 增强了基于 OBS 对象存储的 **冷热分层表（Cold & Hot Table）** 与计算加速：

- 将历史冷分区通过 `storage_policy` 迁移至 OBS 低成本对象存储，热分区保留在本地高性能盘。
- DWS 9.1 新增 **Disk Cache** 与 **Async I/O** 机制，加速热点冷数据二次扫描，并支持通过 `EXPLAIN WARMUP` 分析缓存预热与本地缓存命中策略。

```sql
-- 查看冷热表或查询的预热执行计划（只读诊断）
EXPLAIN WARMUP SELECT COUNT(*) FROM dw.fact_history WHERE dt >= '2025-01-01';
```

## 6. 回收站（Recyclebin）与防误删管理

- 参数 `ENABLE_RECYCLEBIN = on` 开启后，`DROP TABLE` 与 `TRUNCATE TABLE` 会将对象暂存回收站而非立即物理抹除（`KEEP ttl HOUR` 可配置保留时长）。
- 若需绕过回收站彻底释放空间，需显式附带 `PURGE` 关键字（高危操作，执行前务必确认）：

```sql
-- 彻底物理删表（不可从回收站闪回）
DROP TABLE dw.tmp_stage_old PURGE;
```

## 7. 多方言兼容与 `sql_dialect` 扩展

DWS 除原生 `sql_compatibility`（支持 `ORA` / `TD` / `PG` / `MySQL` 语法兼容模式）外，DWS 9.1 提供 `sql_dialect` 插件进一步对齐异构数仓方言习惯。迁移存量 SQL 时应先通过 `SHOW sql_compatibility;` 确认当前库级兼容模式，避免 `NVL`/`DECODE`/`||` 字符串拼接、`NULL` 与空串 `''` 处理语义差异。
